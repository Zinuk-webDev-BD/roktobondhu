# রক্তবন্ধু

রক্তদাতা, হাসপাতাল ও ব্লাড ব্যাংককে এক জায়গায় যুক্ত করার একটি ওয়েব ব্যবস্থাপনা সিস্টেম। এখানে রক্তের স্টক দেখা, জরুরি রক্তের অনুরোধ করা, উপযুক্ত দাতা খোঁজা ও ব্যাগ বরাদ্দ করা যায়।

**লাইভ প্রজেক্ট:** https://roktobondhu-alpha.vercel.app

**Hack the Vibe 2026 | ট্র্যাক:** World Problem Solver (স্বাস্থ্যসেবা)

**বাছাই করা দুটি Advanced Challenge:** A05 (Concurrency ও Transaction Management) এবং A03 (Advanced Security ও Access Control)

## সমস্যা

জরুরি মুহূর্তে সঠিক গ্রুপের রক্ত ও যোগ্য দাতা খুঁজে পাওয়া কঠিন। অনুরোধ চলে ফেসবুক পোস্ট ও ফোনকলে, ফলে একই ব্যাগ দুই রোগীকে বরাদ্দ হওয়ার, বা সদ্য রক্ত দেওয়া দাতার কাছেও অনুরোধ যাওয়ার ঝুঁকি থাকে। রক্তবন্ধু হাসপাতাল, দাতা ও ব্লাড ব্যাংকের স্টককে এক জায়গায় এনে এই ঝুঁকিগুলো সিস্টেমের নিয়ম দিয়ে আটকায়।

## আর্কিটেকচার (সংক্ষেপে)

- `prisma/schema.prisma`: ডাটাবেসের মডেল ও সম্পর্ক। `Allocation.bagId` ও `idempotencyKey` unique।
- `src/middleware.ts`: প্রথম স্তরের লগইন ও ভূমিকা সুরক্ষা। প্রতিটি API-তে আবার যাচাই হয়।
- `src/lib/auth.ts`: সার্ভার-সাইড `requireUser(ভূমিকা)`।
- `src/lib/blood.ts`, `matching.ts`, `requestFlow.ts`: রক্তের গ্রুপের সামঞ্জস্য, দাতার যোগ্যতা, ম্যাচিং ও অবস্থা বদলের নিয়ম।
- `src/app/api/*`: REST API route।
- `src/app/dashboard/*`, `src/app/admin/*`: পেজ।

| ভূমিকা | কাজ |
|---|---|
| দাতা | নিজের প্রোফাইল ও যোগ্যতা দেখা, উপযুক্ত খোলা অনুরোধে সাড়া দেওয়া |
| হাসপাতাল | নিজের রক্তের অনুরোধ তৈরি, সম্পাদনা, বাতিল ও (ব্যাগ বরাদ্দের পর) সম্পন্ন করা; সাড়া দেওয়া দাতার ফোন দেখা |
| অ্যাডমিন | ব্যাগ যোগ ও ব্যবস্থাপনা, সব অনুরোধ দেখা, ব্যাগ বরাদ্দ, সম্পন্ন করা, অডিট লগ, একযোগে পরীক্ষা |

## ব্যবসায়িক নিয়ম

**দাতার যোগ্যতা:** বয়স ১৮–৬০ বছর, ওজন কমপক্ষে ৫০ কেজি, শেষ দানের পর কমপক্ষে ৯০ দিন, এবং নিজে "অনুপলব্ধ" চিহ্নিত না করা। অযোগ্য হলে কারণসহ দেখানো হয়।

**অনুরোধের নিয়ম:**
- একবারে সর্বোচ্চ ১০টি ব্যাগ।
- অতি জরুরি অনুরোধের মেয়াদ সর্বোচ্চ ৩ দিন, জরুরি ৭ দিন, সাধারণ ৩০ দিন।
- একই রোগীর জন্য একই গ্রুপের খোলা অনুরোধ দ্বিতীয়বার জমা দেওয়া যায় না।
- অবস্থা বদলের বৈধ পথ: অপেক্ষমাণ → ব্যাগ বরাদ্দ → সম্পন্ন; অপেক্ষমাণ বা বরাদ্দ অবস্থা থেকে বাতিল। সম্পন্ন, বাতিল ও মেয়াদ শেষ অবস্থা থেকে আর বদলানো যায় না।
- মেয়াদ পেরোনো অপেক্ষমাণ অনুরোধ ও ব্যাগ স্বয়ংক্রিয়ভাবে "মেয়াদ শেষ" হয়।

**গোপনীয়তা:** দাতা অনুরোধে রোগীর নাম দেখেন না। হাসপাতাল দাতার ফোন নম্বর শুধু তখনই দেখে, যখন দাতা নিজে সাড়া দেন।

**দাতা ম্যাচিং:** রক্তের গ্রুপের সামঞ্জস্য, যোগ্যতার নিয়ম, জেলা ও শেষ দানের তারিখ দেখে সাজানো হয়। প্রতিটি সুপারিশের পাশে কারণ লেখা থাকে। অ্যাডমিন দেখতে পান কেন কোনো দাতা বাদ পড়লেন।

## ব্যাগ বরাদ্দ ও একযোগে সুরক্ষা

- হুবহু একই গ্রুপের ব্যাগ আগে, না থাকলে সামঞ্জস্যপূর্ণ গ্রুপ। যে ব্যাগের মেয়াদ আগে শেষ হবে সেটা আগে বরাদ্দ হয়।
- পুরো বরাদ্দ একটি ডাটাবেস transaction-এ হয়। পর্যাপ্ত ব্যাগ না মিললে কিছুই বদলায় না।
- ব্যাগ দখল হয় "অবস্থা প্রস্তুত এবং version মেলে" শর্তে, তাই দুজন একসঙ্গে একই ব্যাগ পায় না।
- বরাদ্দ রেকর্ডে ব্যাগের পরিচয় UNIQUE, ফলে কোডে ভুল হলেও ডাটাবেস দ্বিতীয়বার বরাদ্দ আটকায়।
- idempotency key: ডাবল ক্লিক বা নেটওয়ার্ক retry-তে একই বরাদ্দ দুইবার হয় না।
- বরাদ্দ হওয়া অনুরোধ বাতিল করলে ব্যাগ আবার স্টকে ফেরে। সম্পন্ন করলে ব্যাগ "ব্যবহৃত" হয়।
- অ্যাডমিনের "একযোগে পরীক্ষা" পেজে ১টি ব্যাগের জন্য ১০টি অনুরোধ একসঙ্গে ছাড়লে ঠিক ১টি সফল হয়।

## নিরাপত্তা

- সব ফর্ম ও API-তে সার্ভারে Zod দিয়ে তথ্য যাচাই, ফিল্ড অনুযায়ী বাংলা error বার্তা।
- ভূমিকা অনুযায়ী API ও পেজের অনুমতি।
- রিসোর্স-ভিত্তিক অনুমতি: অন্য হাসপাতালের অনুরোধ দেখা, বদলানো বা সম্পন্ন করার চেষ্টায় 403 আসে এবং চেষ্টাটি অডিট লগে ব্যর্থ এন্ট্রি (`ACCESS_DENIED`) হিসেবে থাকে।
- অডিট লগে বরাদ্দ, বাতিল, সম্পন্ন, প্রোফাইল বদল, লগইন ও আটকানো চেষ্টা জমা থাকে।
- ব্যবহারকারীকে ভেতরের ত্রুটির বিবরণ না দেখিয়ে সাধারণ বাংলা বার্তা দেখানো হয়।
- পাসওয়ার্ড হ্যাশ করে রাখা হয়, আসল `.env` GitHub-এ যায় না।
- সেশন JWT (HS256), মেয়াদ ৮ ঘণ্টা। কুকি `httpOnly`, `sameSite=lax`, প্রোডাকশনে `secure`। প্রতি অনুরোধে ডাটাবেসে ব্যবহারকারী সক্রিয় কি না যাচাই হয়, তাই নিষ্ক্রিয় করা ব্যবহারকারীর পুরনো টোকেন কাজ করে না।
- লগইনে ব্রুট-ফোর্স আটকানো: একই IP ও ইমেইলে ১৫ মিনিটে ৫ বার, একই IP থেকে মোট ২০ বার। সফল লগইনে ইমেইলের গণনা শূন্য হয়। আটকানো চেষ্টা অডিট লগে থাকে।
- লগইনে ইমেইল আছে কি না বাইরে থেকে বোঝা যায় না (একই বার্তা, সমান সময়)।
- নিরাপত্তা হেডার: `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, HSTS ও `frame-ancestors`। API-র উত্তরে `Cache-Control: no-store`।

## ডেমো অ্যাকাউন্ট

## বিচারকদের জন্য দ্রুত যাচাই

**A05 (Concurrency):** অ্যাডমিন হিসেবে লগইন করে `/dashboard/race-demo` পেজ খুলুন এবং পরীক্ষা চালান। স্টকের একটি ব্যাগের জন্য একসঙ্গে অনেক অনুরোধ যায়, আর ঠিক ১টি সফল হয়। বাকিরা "ব্যাগ নেই" বার্তা পায়। অডিট লগে ফলাফল থাকে।

**A03 (Security):**
1. অ্যাডমিন হিসেবে "সব অনুরোধ" থেকে hospital1-এর একটি অনুরোধ খুলুন এবং ঠিকানার শেষের অংশটি (অনুরোধের আইডি) কপি করুন।
2. লগআউট করে hospital2 হিসেবে লগইন করুন এবং `/dashboard/requests/<আইডি>` ঠিকানা খুলুন। "এই অনুরোধ আপনার নয়" পেজ আসবে।
3. অ্যাডমিন হিসেবে আবার ঢুকে "অডিট লগ" খুলুন। `ACCESS_DENIED` নামে একটি ব্যর্থ এন্ট্রি দেখা যাবে।

**M06 (ভুল তথ্য):** হাসপাতাল হিসেবে অনুরোধ ফর্মে ১১টি ব্যাগ দিন, বা অতি জরুরি অনুরোধে ১০ দিন পরের তারিখ দিন। সার্ভার থেকে ফিল্ড অনুযায়ী বাংলা error আসবে।

## স্থানীয়ভাবে চালানো

1. প্রজেক্ট নামিয়ে নিন এবং নির্ভরতা বসান:
```
npm install
```
2. `.env.example` কপি করে `.env` নাম দিন এবং নিজের মান বসান। `JWT_SECRET` বানাতে:
```
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```
3. টেবিল বানান এবং নমুনা তথ্য ঢোকান:
```
npx prisma db push
npm run db:seed
```
4. চালু করুন এবং `http://localhost:3000` খুলুন:
```
npm run dev
```

## জানা সীমাবদ্ধতা

- রক্তদান ও যোগ্যতার তথ্য সাধারণ সচেতনতার জন্য। চূড়ান্ত সিদ্ধান্ত ব্লাড ব্যাংকের চিকিৎসক নেন।
- ব্লাড সেন্টারের ফোন নম্বর বাংলাদেশ রেড ক্রিসেন্ট সোসাইটির ওয়েবসাইট থেকে নেওয়া। নম্বর বদলাতে পারে, তাই যোগাযোগের আগে যাচাই করুন।
- রেট লিমিট সার্ভারের মেমরিতে থাকে। সার্ভার রিস্টার্ট হলে বা একাধিক instance (যেমন Vercel serverless) চললে সীমা আলাদাভাবে গোনা হয়। পুরো সুরক্ষার জন্য Redis লাগবে।
- পূর্ণ Content-Security-Policy (`script-src` সহ) বসানো হয়নি, কারণ Next.js-এর জন্য nonce-ভিত্তিক সেটআপ লাগে।
- ডেমো অ্যাকাউন্ট ও নমুনা তথ্য শুধু প্রদর্শনের জন্য। আসল ডেটার ওপর `db:seed` চালাবেন না।
